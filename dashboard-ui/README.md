# dashboard-ui

The team dashboard's frontend (Vite + React + TypeScript). See `docs/adr/ADR-013-cross-project-dashboard.md` §6
for the full design rationale (why a JS framework, why a static build, why `vite-plugin-singlefile`).

## Usage

```
npm install          # first run only
npm run dashboard     # = npm run data (python -m scripts.dashboard --json) + vite build
```

Open `dist/index.html` directly (`file://...`) - no server. `/dashboard` (the Claude Code
skill, one directory up) does this for you and reports the path.

## Layout

- `src/lib/types.ts` - mirrors `scripts/dashboard.py`'s `emit_json()` shape exactly (camelCase).
  Python is the source of truth; if the two drift, fix this file, never the reverse.
- `src/lib/timelineModel.ts` - pure, framework-free swimlane/loop-arc model (`buildTimelineModel`,
  `parseHandoff`, ...). Unit-tested: `npm run test` (Vitest).
- `src/components/` - one component per dashboard section. `TeamSwimlaneTimeline.tsx` /
  `TimelineStackedList.tsx` are the desktop/mobile pair sharing one `TimelineModel`.
- `data/dashboard-data.json` - generated by `npm run data`, gitignored, statically imported by
  `App.tsx` (bundled at build time - never fetched at runtime, which would break under `file://`).

## Commands

- `npm run dev` - live dev server (HMR) for iterating on components. Not the production path -
  see ADR-013 §6 for why the build target is a static file, not a running server.
- `npm run build` - typecheck (`tsc -b`) + `vite build`.
- `npm run test` - Vitest, `src/lib/**/*.test.ts` only (no component/rendering tests for v1).
- `npm run lint` - oxlint.
- `npm run dashboard:live` - opt-in live-updating server (see below). Never run automatically
  by anything else - `/dashboard`, `npm run dashboard`, and the Artifact preview all stay the
  static, zero-server default (ADR-013 §6) regardless of whether this exists.

## Live mode (`npm run dashboard:live`)

An explicitly user-started local server that keeps the dashboard current without manually
re-running `npm run dashboard`/`/dashboard`. This is **additive**, not a replacement for the
default: nothing else in this project starts it for you, and stopping it (Ctrl-C) leaves
everything exactly as the static build already worked.

How it works: every `--poll-seconds` (default 8), it re-runs `npm run data` (a cheap Python
scan) and hashes the result (excluding `dashboard-data.json`'s own `generated` timestamp, which
changes on every scan regardless of whether anything real did - hashing the raw file caused a
rebuild on literally every poll before this exclusion, a real bug caught testing this feature,
not a hypothetical one). Only on a genuine change does it run `vite build` and push a `reload`
event (Server-Sent Events, `EventSource` - no library) to any open browser tab, which then does
a full page reload. The staleness window is the poll interval, not instant - this polls rather
than using `fs.watch` deliberately, since `fs.watch`'s recursive mode has real cross-platform
gaps this project already has to account for elsewhere (see `install_helper.py`'s own
Windows-PATH handling).

`dist/index.html` itself, and everything that builds it (`/dashboard`, `npm run dashboard`, the
Artifact extraction script), is **never modified** by live mode - the reload snippet is
injected only at serve time, in memory, for requests this server itself answers.

Binds to `127.0.0.1` by default - not reachable from other devices. Pass `--host 0.0.0.0` to
expose it on your LAN (e.g. to check it from a phone); the server prints a plain warning when
you do, since your real project/cost data sits behind that URL once it's reachable off this
machine. `--port` (default 4174, distinct from `vite preview`'s 4173) and `--poll-seconds` are
also available - `node live-server.mjs --help`.

## Design system credit

The Tailwind token-system shape (an elevation ramp, semantic border/accent tokens, an
`@layer components` pattern) and the `src/components/ui/` primitives were adapted from
[hoangsonww/Claude-Code-Agent-Monitor](https://github.com/hoangsonww/Claude-Code-Agent-Monitor)
(MIT License, © Son Nguyen) - a real Claude Code session/agent monitoring dashboard, chosen
over a generic component kit at the user's request. We ported the pattern and structure, not
the code or its literal color palette: our tokens stay in this project's own warm teal-on-cream
family (light + dark via `prefers-color-scheme`), never that source's indigo-on-near-black, and
none of its Express/WebSocket/SQLite backend applies here - this app stays 100% static-JSON,
zero-server (see ADR-013 §6).
