# Release 0.33.1 - the team uses more of the platform (2026-07-29)

A follow-on to [0.33.0](0.33.0.md) (read that first - it is the substance of this cycle).
0.33.1 adopts the valuable-but-unused Claude Code capabilities identified by the
2026-07-29 platform audit, plus a fix for a live pain: PDFs handed to the team.

## What you will notice

- **Documents convert instead of confusing.** Hand the team a PDF, DOCX or spreadsheet and
  it routes through the bundled converter (`scripts/convert_file.py` - dependencies
  vendored, zero installs, built for locked-down corporate machines). A new `--layout`
  mode keeps PDF columns and tables readable. A new hook mechanically blocks the old
  failure (reading the binary bytes, PowerShell hand-parsing) during engagements and
  prints the exact command to run instead. Scanned pages are escalated to you, never
  guessed.
- **A progress panel while the team works.** The engagement's gates (brief, build, tests,
  review, QA, done-gate, close) appear in Claude Code's native task list, ticked as their
  evidence lands - a glanceable view that costs no console space.
- **A status line.** Once wired, the terminal's status bar shows "team dormant" or the
  live engagement (name, status, phase) plus session cost - rendered by a shell script,
  costing zero tokens.
- **Compaction stops losing the thread.** When a long session is compacted or resumed, a
  new SessionStart hook re-briefs the model: which engagement is active, and that the
  answers you already gave live on disk and are not to be re-asked (a consent No stays a
  No). Silent in every session that never engaged the team.
- **Mistakes surface one edit sooner.** A PostToolUse hook lints Python the moment a
  builder writes it (syntax always, ruff when installed) and feeds problems straight back,
  instead of waiting for the review gate.

## For the human operator: four apply commands (one optional)

Hook and settings changes remain yours alone to apply. This release stages three:

```
bash scripts/apply-document-redirect.sh   # PDF/Office inputs route to the converter
bash scripts/apply-session-brief.sh       # compaction/resume re-brief (ADR-011)
bash scripts/apply-post-edit-lint.sh      # lint feedback after each Python edit
bash scripts/apply-statusline.sh          # optional: the status line (repo-scoped setting)
```

Each is idempotent, and each hook is engagement-scoped: dormant sessions behave as
standard Claude Code, and every hook fails open.

## Deliberately deferred

- **Notification pings** (a push message when the team is waiting on you): excluded by the
  user's decision for this batch.
- **Running the eval sweep as a forked background skill** (`context: fork`): needs a
  verification spike first - proof that the project's guard hooks bind to forked-skill
  subagents exactly as they do to Task subagents. Not adopted on trust.
- **Dynamic Workflows pilot**: structurally mismatched with the team's question-gated
  front door (workflows forbid mid-run user input); waits for a bounded, gate-free
  sub-task that actually needs the fan-out, plus the same guard-binding verification.
