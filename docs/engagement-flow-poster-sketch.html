1 · Engagement Lifecycle end to end

🎩Team invoked?

/engage, another team command, or asking in words for "the team" / "Morgan" / "the PM"

NO
💤Plain Claude Code session

Team stays dormant. Only Layer 0 hooks & guards (panel 2) stay armed.

YES — Phase 1 · Open
🔎Step 0: ONE compound probe call

Operating guide, plugin root, interpreter (python3→python→py), run mode, team version, analyser inventory, codebase-map header + §3 history, newest changelog block.

⬇️
📣Opening banner — always first

🎩 Morgan intro + team version + /meet-the-team offer. What's-new: one line if version changed; "current release" form if no record; nothing if unchanged; silently omitted if changelog unreadable.

⬇️
Concrete target or inputs given?

No (bare /engage): ask ONE question — "where is the code / input?" — and wait; loop until a target exists. Never invent one. Yes: continue.

⬇️
⚠️Two VERBATIM safety disclaimers

⚠️ Execution safety (static by default; user responsible for handed-over code being safe to run) · 🛡️ Data safety (everything shared reaches the model provider; data/raw/ hard-blocked; pseudonymised ≠ anonymous).

⬇️
🗳️ONE batched AskUserQuestion call

Only the applicable questions (≤4 per call, ≤4 options each, short headers): work-type (only if ambiguous) · execution-consent INTENT · data attestation. Answers recorded once, never re-asked per file/command.

◇ Execution consent (default No)
✍️"Yes" = intent only

The USER personally types touch <abs-path>/.claude/.exec-consent (PowerShell/cmd variants on Windows). Human-only grant — the model is blocked from writing it. Marker verified before any execution; no marker → still blocked.

🚫"No — static only"

Any existing marker is DELETED (fail-safe close). Dynamic/perf findings stay 🧠 inferred.

◇ Data attestation (when data involved)
🟢"Yes — synthetic/masked, no prohibited PII" or "no data involved"

Proceed. data/raw/ stays hard-blocked regardless.

🧪"No / unsure"

Route to /prepare-data: masking pipeline (ingest + masking-schema + validate_masking, key from MASKING_KEY) — prefer fully synthetic.

⬇️  Phase 2 · Classify & gather
Classify the work

Route by deliverable type — never assume a detection rule. Phased engagements re-classify per phase: the moment a phase produces deliverable code it runs under the build chain.

Problem / idea
💡Discovery → requirements

/write-brd, /elicit-requirements, /brd-to-fsd → then build (full SDLC).

Review
Security-sensitive surface?

Auth, parsing, DB, external I/O, crypto, secrets, PII → offer review + /security-audit (recommended; re-offered at the review's close).

📋LOCKED review menu — one call

Q1 Depth: Quick ⊂ Deep ⊂ Audit · None · Q2 Performance review: yes/no (static, 🧠/📄) · Q3 Fix-cycle: report only / apply fixes / fix→re-review loop ⟲ (single source of truth, never re-asked).

Q1 = None and Q2 = No?

Nothing to run — say so and return to the outcome question. Never invent work.

Build from requirements
🏗️→ /build-solution

Orchestrator-workers. Inputs gathered FIRST (path / repo / branch / paste), existence verified.

⬇️  Phase 3 · Plan & gate
🗂️LOCKED artifact menu — two stages

Stage 1: Consolidated Delivery Report (default) / separate artifacts / both. Stage 2 (if separate/both): grouped multi-selects — Spec docs · Reviews · Handover; rarer templates via "Other". Everything ships .md + .html.

⬇️
📄Engagement Brief + START-HERE living index created together (⏳)

Decisions, assumptions, routing plan; index seeded with the gates ahead. Every artifact write appends a START-HERE row IN THE SAME TURN — the index is the engagement's external memory and survives compaction.

⬇️
Go-ahead gate

Proceed as briefed → Phase 4 · Adjust → back to the menu · Stop → engagement ends unstarted.

⬇️  Phase 4 · Delivery (panel 3) → then ◇ blocked?
Phase 4a · Blocked path
🛑Turn ends needing user input

START-HERE set ⛔ with the outstanding list (open questions + every gate not yet run). Turn ends saying plainly "NOT closed — outstanding: …". No summary email, no delivery report before close.

🔁Resume — two routes

Same session: user answers → ⛔ flips to ⏳, answer logged. Cold resume (new session): reads START-HERE + interim artifacts as the state of record, honours recorded decisions and evidence, works the outstanding list top to bottom.

Work complete
✅Phase 5 · Close sequence (panel 4)

The only path to ✅. Ends with the delivery report, summary email and concrete next-step options; human sign-off is the user's act.

2 · Layer 0 — Always-On Hooks & Guards every session, dormant or not

PreToolUse chain — every matching tool call, in order
🛡️Permission deny rules .claude/settings.json

Hard-deny read AND write on data/raw/** (any depth). Read-only denies on .env*, secrets/**, *.pem, *.key.

⬇️
🛡️guard-raw-data.py Read · Grep · Glob · Bash

Any touch of data/raw/ → 🛑 BLOCK. Raw transaction/comms data must never reach the model.

⬇️
🛡️guard-code-execution.py Bash only

Command split on ; && || | \n ` $(; each segment: team-script allow-list (python -m scripts.*, bundled-copy paths, bash scripts/*.sh) → allow consent-free. Executes other code → ◇ .claude/.exec-consent exists or CST_ALLOW_EXEC=1? Yes (human created it) → allow · No → 🛑 BLOCK: static by default, consent is a human act. Lexical guard — consent-recording + safety net, not a sandbox (ADR-002).

⬇️
🛡️guard-consent-writes.py Write · Edit · MultiEdit · NotebookEdit · Bash

Any MODEL write to the consent marker, settings files or hook files → 🛑 BLOCK — the model can never grant itself consent or weaken a guard. Read-only mentions (echo/grep) allowed.

⬇️
✅Tool runs
UserPromptSubmit — every user turn
🎩persona_anchor.py

◇ Project-root artifacts/START-HERE.md open (⏳/⛔)? Yes → inject the ≤8-line Morgan persona + discipline anchor (survives compaction). No → silent; team stays dormant. Anchored to CLAUDE_PROJECT_DIR, never the shell's wandering cwd.

Stop hook — model tries to end its turn
🛑dod_stop_gate.py — warn-first

◇ Project START-HERE open? → run the mechanical DoD checker over artifacts/. ◇ Findings? Yes → block the stop ONCE with a FIX-LIST: the MODEL then auto-fixes deterministic defects, escalates judgement calls, or ends plainly saying "NOT closed — outstanding: …". No re-fire in the same stop cycle. Otherwise silent.

3 · Phase 4 — Delivery Machine agile loop ⟲ + the mandatory code chain

📣Right-size OUT LOUD

Agent count + why, stated before any fan-out. Multi-agent ≈ 15× tokens: leanest set that fits (1 agent fact-finding · 2-4 comparison · minimal sufficient chain for delivery).

⬇️
🧭Route by deliverable type (roster: Morgan + 16)

Spec — Amara · rules — Mateo · pipeline/utility/infra — Kenji · analysis/FP/MI — Ana · tuning — Theo · ML — Mei (validated by Viktor) · independent QA — Linh · code review — Ravi · performance — Thabo · compliance — Layla · coverage/DQ — Yuki · SMEs — Hassan/Camila/Cleo · mechanical scoring — Pip. Model tiers: opus for last-word judgement + the orchestrator; sonnet build/advisory; haiku scorer.

⬇️
📨Explicit, non-overlapping briefs

Objective · scope boundary · inputs · output format · hard return budget ≤ ~1,500 tokens (detail goes to the artifact). Coordination via shared artifacts — the "blackboard" — not chatter. A subagent inherits none of the conversation.

⬇️
👥Specialists work

Advisory agents (SMEs, validators, reviewers) hold NO Write/Edit — they recommend, Morgan routes. Build agents implement.

⬇️
🕵️PM challenge — sceptic, not relay

Spot-check don't re-score: every Critical, anything regulated, thin evidence, a sample of the rest AND of the filtered set (promote wrongly-filtered findings). Verify 📊 vs 🧠 vs 📄 — never let inference reach the user as fact.

◇ Deliverable code produced? → the chain attaches, no workflow exempts it
🧪Tests

Project's own framework — never assumed; exact command recorded.

⬇️
🔍Code review (Ravi)

◇ Findings → fix & re-review ⟲ per the Q3 fix-cycle answer, until no Criticals or the user stops.

⬇️ ◇ execution-consent marker present?
YES
✅Independent QA (Linh)

Append-only test cycles; failed verdicts preserved as-found; QA suites RETAINED under artifacts/. ◇ Fail → route fix, new cycle ⟲ · Pass → on.

NO
🧠Static-only DoD path

QA verdict stays 🧠, DoD marked PARTIAL, untested code named as residual risk; the close offers "grant consent → suite runs → verdict upgrades".

⬇️
📄Index discipline — every write

Each artifact write appends a START-HERE row in the same turn. Interim names only: review-pass-N, qa-cycle-N, interim-* + the interim banner. delivery-report / final-* / the email are close-only names.

⬇️
More iterations needed?

Yes → back to right-sizing ⟲. No hard cycle limit exists — the brake is the user at each gate (or budget/turn caps in the eval harness). No → Phase 5.

4 · Phase 5 — Close Sequence the only path to ✅

🔗 Citations gate

check_citations: TO-VERIFY citations ship FLAGGED with source permalinks (register URL → register scheme → official search / "to be confirmed"; never invent a URL). Never blocks the close; never a close-time verification question. Limitations note in report + one line in the email. User later says "mark X verified" → register overlay updated.

⚙️ Mechanical DoD gate

check_artifacts --fix, run as a FIX-LIST ⟲. Auto-fix (team): MISSING-HTML, index defects, roster names, premature final/summary, STALE-STATUS, paths, evidence tags, CODE-NO-TESTS / CODE-NO-QA (route the missing chain step). Escalate (question tool): evidence contradictions, unverifiable sign-off authority, scope calls, STALE-DOCSTATUS (a stated "pending human sign-off" passes).

⚖️ Reconciliation sweep

EVERY produced or touched document, including the deliverable README and module docstrings: one authoritative set of counts / ranges / findings enumerations; late-cycle changes propagated; struck citations swept from every file; dead interim prose removed; document-control statuses closed out; QA evidence retained — a 📊 measured tag with no surviving artifact downgrades to 🧠.

🗺️ Codebase map

ADR-003, a DoD gate: durable architecture facts with 📊/🧠 tags, dates, SHA anchors; corrections/deprecations dated; history row appended. Maps the CODE, never team activity. PM-written, ≤ ~200 lines.

🖨️ Render

Every .md artifact gets its .html sibling (render_html).

✉️ Delivery Report + email

Both close-only, written now. The engagement-summary email: .txt in artifacts/ (the one artifact never rendered to HTML), signed as Morgan, "Hi," if the requester's name is unknown, states the token + agent footprint, repeats the responsibility notes, NEVER offers a call or meeting.

🏁 Finalise START-HERE — last of all

The FINAL state change: Status → ✅ CLOSED + date, verdict and footprint filled, ⚠️-outstanding replaced with "Nothing — closed", interim banners stripped from every artifact that became final.

🖋️ Next steps & sign-off

Short summary + concrete next-step options with a recommendation — never a dead end. Human sign-off is the one DoD item only the user can perform.

❓ Cross-cutting rules

  • Every choice via AskUserQuestion — ≤4 questions/call, ≤4 options, headers; single-select for exclusive axes, multi-select for independent picks, one axis per question.
  • 🎩 voice first line of every Morgan turn; specialists by name; console clean — detail lives in artifacts, not the TUI.
  • Evidence basis on every data claim: 📊 / 🧠 / 📄.
  • Memory: general lessons → house rules; engagement-specific → the working project's CLAUDE.md / codebase map. The plugin accrues no project memory.
  • Compaction resilience: START-HERE as external memory + the persona anchor each turn.

🗃️ Artifact timeline (on disk)

  • Open (Phase 3): engagement-brief.md/.html · START-HERE.md/.html (living, updated every write).
  • Delivery (Phase 4): fsd · rtm · review-pass-N · qa-cycle-N / qa-handover · interim-* · deliverable code + tests + QA suites · analysis packs — each with .html.
  • Close (Phase 5): delivery-report · developer-handover (if chosen) · engagement-summary-*.txt · docs/codebase-map.md · finalised START-HERE.
  • All artifacts/ content is git-ignored by the team repo's own hygiene.

🏅 Definition of Done

  • Traceable — RTM spine: BRD → FSD → code → test → regulatory obligation.
  • Tested — known true/false-positive cases; exact command recorded.
  • Independently QA'd — full cycle history, evidence preserved.
  • Code-reviewed — no open Criticals; dispositions; developer guidance.
  • Performance- and compliance-reviewed where routed.
  • Critiqued vs a named standard — 5 C's · BABOK · ISO/IEC 29119 · SR 11-7-style.
  • Reconciled at close · dual-format artifacts · summary email · truthful lifecycle state · human sign-off.
  • Static-only variant → DoD PARTIAL with named residual risk.
